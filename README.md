# Protobuf Scala runtime

A pure Scala implementation of the protobuf wire-format primitives used by
[ScalaPB](https://scalapb.github.io/). It supports Scala.js, Scala Native, and the
JVM without depending on Google's Java runtime.

## Using the library

ScalaPB normally selects this runtime for the relevant platform. For direct use
in an sbt cross-project with sbt-crossproject installed:

```scala
libraryDependencies += "com.thesamet.scalapb" %%% "protobuf-runtime-scala" % "0.8.16"
```

For a JVM-only project, use `%%` instead of `%%%`. `0.8.16` is the latest release
tag in this checkout; the fixes described below require the next release or a
locally published build. Choose the runtime version required by your ScalaPB
version. Do not place this library and `protobuf-java` on the same JVM classpath:
both define classes in `com.google.protobuf`.

| Component | Build/test version |
| --- | --- |
| Scala | 2.12.21, 2.13.18, 3.3.8 |
| Scala.js | 1.22.0 |
| Scala Native | 0.5.12 |
| sbt | 2.0.10 |
| Build JDK | 21 |
| JVM bytecode/API target | Java 8 |
| CI JavaScript runtime | Node.js 22 |

Scala 3 stays on the 3.3 line to preserve the existing consumer baseline.
Building and running the test framework requires a newer JDK than the published
library's Java 8 target. CI runs every Scala version on every platform and a
previously compiled downstream consumer on Java 8 for each Scala line.

## Supported API and limitations

- `ByteString` implements immutable byte values, slices, copies, stream access,
  equality, hashing, and strict UTF-8 validation. The deprecated `bytes` accessor
  returns a defensive copy of the visible slice; use `toByteArray()` instead.
- `CodedInputStream` and `CodedOutputStream` provide the implemented protobuf
  scalar, tag, byte/string, and wire-format operations. Ordinary `readString()`
  uses replacement decoding; `readStringRequireUtf8()` rejects malformed UTF-8.
- Input streams default to a 64 MiB size limit. `setSizeLimit` changes that limit;
  it applies to stream inputs, including prefetched bytes and large reads.
  Array inputs are bounded by their supplied offset and length instead.
- Unknown-group skipping defaults to 100 nested groups. `setRecursionLimit`
  controls that depth. This does not track recursion in external message parsers.
- `pushLimit`/`popLimit` delimit embedded messages. A limit restricts parsing,
  not how much the input stream may prefetch. `enableAliasing` is a no-op.
- `Descriptors`, `DescriptorProtos`, `Message`, `GeneratedMessage`,
  `GeneratedMessageV3`, and `UnknownFieldSet` include compatibility stubs for
  generated-code compilation. They do **not** implement Google's reflection,
  descriptor construction, or Java message runtime. Some methods throw
  `NotImplementedError`; others return placeholders. Use ScalaPB's supported
  descriptor/message APIs instead.

This is a focused runtime, not a complete implementation of the Google Java API.

## Development and tests

Install JDK 21, sbt, Node.js, and Clang. On Ubuntu, Native builds may also need
`libgc-dev` and `libunwind-dev`. With Nix, `nix-shell` provides the development
commands (using your configured nixpkgs).

```sh
sbt +test
sbt 'scalafmtCheckAll; scalafmtSbtCheck'
# A single compiler/platform:
sbt '++2.13.18; protobufRuntimeScalaJVM/test'
sbt '++3.3.8; protobufRuntimeScalaJS/test'
sbt '++2.12.21; protobufRuntimeScalaNative/test'
```

The shared regression suites cover:

- Every slice and nested slice in a bounded array, equality symmetry, hashes,
  defensive copies, invalid indices, offset/length validation, and overflow.
- Every one- and two-byte UTF-8 input, every Unicode code point (including
  rejecting surrogates), three/four-byte lead/second-byte combinations,
  truncated sequences, corrupt continuations, and strict string decoding.
- Varint boundaries at every bit, seeded random values, malformed/truncated
  encodings, fixed-width truncation, tags, and all unknown-field wire types.
- Array slices and streams returning 1, 2, 7, or 4096 bytes per read; reads and
  skips around 4096-byte buffer boundaries; nested limits; exact size limits;
  recursion boundaries; and invalid stream read results.
- Output buffer sizes and representations, complete array range validation,
  exhausted destinations, and partial stream failures.
- ScalaPB-generated nested messages, packed/unpacked fields, maps, oneofs,
  unknown-field preservation, and malformed payloads.
- Managed test sources generated by Google's protobuf Java implementation, checked
  against encoders, decoders, and size calculations on every platform.

sbt generates the wire fixtures automatically before compiling tests. The
`wireFixtureGenerator` Java-only subproject resolves the pinned `protobuf-java`
dependency and runs in a separate JVM, keeping Google's identically named classes
out of the runtime and test classpaths. All platforms consume the same generated
source under `target/out/jvm/u/wirefixturegenerator/generated-test-sources`; it is not
committed or included in published artifacts.

Generation is cached by the generator's compiled classes and dependency jars.
Changing the generator or its protobuf dependency, or deleting its output,
regenerates the fixtures. To run generation explicitly:

```sh
sbt generateWireFixtures
```

The generator is aggregated so Scala Steward discovers its dependency, but is
not published or added to runtime classpaths and stays on a single compiler.
Update `ProtobufJava` in `build.sbt` to change the reference implementation, then
run `sbt +test` to check all compiler/platform combinations.

## Release compatibility checks

The `integrationJVM`, `integrationJS`, and `integrationNative` test projects
compile managed messages from `integration/shared/src/test/protobuf` with ScalaPB.
Their classpaths exclude both Google's Java runtime and the previously published
Scala wire runtime so the tests exercise this checkout. They are not published.

```sh
sbt +test
sbt '+protobufRuntimeScalaJVM/mimaReportBinaryIssues'
JAVA8_HOME=/path/to/jdk8 sbt '+binaryConsumer/compatibilitySmoke'
```

MiMa checks the JVM API against 0.8.16. The binary consumer is compiled against
that release, then run unchanged against the candidate. `JAVA8_HOME` selects the
runtime for this fork; without it the check uses the build JDK. CI always supplies
Java 8. Integration tests also compile the consumer source against the candidate.
The `bytes` getter retains its JVM signature, but its change from a Scala `val`
to a `def` affects stable-path source uses; see [release notes](RELEASE_NOTES.md).

## Dependency updates

Scala Steward pins Scala 3 to the `3.3.` prefix, allowing patch releases while
preserving the consumer baseline even when a newer LTS is available. The rules
cover the JVM compiler/library, both Scala.js module naming forms, and Native's
`scala3lib` (whose version also includes the Native version). Other dependencies,
including the generator's `protobuf-java`, remain eligible for normal updates.

## Publishing

Publishing uses sbt-ci-release and Maven Central's **Central Portal**, not the
retired OSSRH service. The release workflow runs the complete CI matrix before
publishing, uses full Git history for version calculation, and publishes snapshots
from `master` and releases from `v*` tags.

Maintainers must ensure the `com.thesamet.scalapb` namespace is available in the
Central Portal and configure these GitHub Actions secrets:

- `SONATYPE_USERNAME` and `SONATYPE_PASSWORD`: the two parts of a **Central Portal
  user token**, not an OSSRH token or account password.
- `PGP_SECRET`: the base64-encoded signing private key.
- `PGP_PASSPHRASE`: its passphrase.

See [sbt-ci-release's publishing guide](https://github.com/sbt/sbt-ci-release#readme)
and [Central Portal tokens](https://central.sonatype.org/publish/generate-portal-token/).
No manual `publishTo` override or separate sbt-sonatype/sbt-pgp pin is required.
Never run `ci-release` just to validate the build: it publishes artifacts. Use
`+test`, `+package`, and `+makePom` for local validation instead.
